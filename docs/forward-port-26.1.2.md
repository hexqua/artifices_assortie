# 26.1.2への継続移植

1.21.1の開発基準は `main`。26.1.2の初回移植元は `f75d016c33c5bc72560d169ca1679525d85de376`。継続移植では `26.1.2-main` を起点に機能または修正ごとの作業ブランチを作り、対象の非mergeコミットを古い順に `git cherry-pick -x` する。移植先の補正と挙動テストを同じ作業ブランチでレビューする。port依頼の範囲ではローカルコミット可。公開・マージは別の操作として扱う。

## 版ごとの動作

- 親MODの変更は、Gradleで固定した配布jarを基準に確認する。Iron's Arms 'n Artifice 26.1.2-1.2.0 のブロック耐久計算では、未損傷ブロックにも初撃のダメージをそのまま適用する。採掘モディファイアは弾の `BREAKS_BLOCKS` を有効にする。依存更新時は高威力での初撃、通常弾で壊せるブロック、実際の弾の貫通回数を再確認する。
- オイルの盾判定には同じ対象・方向のバニラ負傷／治癒スプラッシュを用いる。残留雲の持続時間倍率は基本効果とカスタム効果の両方に掛かる。
- 幸運メダルのMobドロップは戦利品計算時の両手、採掘のFortuneは破壊した弾を参照する。直撃・即時爆風の死亡ドロップは転送し、遅れて発生した炎上死には死亡時の転送を行わない。
- Create・Spellbooks・Malumの連携はこの版では無効。通常レシピを生成し、Spell Imbuementのアイテムと保存コンポーネントIDは維持する。新規ワールドを検証基準にする。
- JEIはクライアントの任意依存。鍛冶のサーバー判定、同期された素材・タグ、JEIの具体例、拡張前後の銃の区別を確認する。

## 検証

Java 25でCLIの `runData` を実行し、生成物の追加と旧出力の残存を確認する。`build` と `runGameTestServer` を実行する。JEIに触れる場合は `runGameTestServer -PwithoutJei` でも鍛冶を確認する。IDE同期は `neoForgeIdeSync`。ゲームディレクトリは `run/26.1.2` とし、1.21.1の手動ワールド・設定と分ける。ゲーム用の起動構成は `runClient` と `runGameTestServer` を使う。

クライアントでは鍛冶素材設定の変更・再接続、JEIのレシピ表示、拡張済み銃の区別、装弾・予備弾表示、照準・反動、オイルの音と描画を確認する。PRの比較先は `26.1.2-main`。移植元SHA、意図した仕様差、自動検証とクライアント確認の結果を添える。
